# Complex Blender materials for OVRTX

Build the richest material justified by its physical construction and visible
features. Keep consequential populations, mapping fields and interface normals
independently editable. Choose the requested OVRTX mode explicitly: Cycles, OVRTX
PT and OVRTX RTPT are separate validation targets.

For reference reconstruction, retain the image-material bundle's analysis,
architecture, spatial design, map contracts and review. For an existing finish,
preserve accepted geometry, color, coherent motifs and artist assignments while
adding the requested mechanisms. A synthetic capability study needs no invented
photographic evidence. Complexity is not a reason to activate every shader lobe.

## Discover the actual authoring path

Use the host Blender workflow and the project's current add-on/runtime contract.
Inspect installed Principled sockets, translator diagnostics and supported node
operations. Record the add-on revision, SDK and render mode; do not silently
replace the backend or build a parallel bridge. A static socket or authored USD
input proves neither native consumption nor visual fidelity.

Use standard editable Blender nodes and named groups so the add-on translates
them to MaterialX/OpenPBR. Expose physical scale, coverage, roughness, relief and
mapping controls through ordinary Value/RGB nodes where practical. Retain stable
node identities for sparse numeric updates. Unsupported nodes must produce an
explicit finding; bake only the affected requested contribution when necessary.

## Design the material

Write a compact layer/field table: mechanism, physical owner, scale, coordinates,
property outputs, composition, controls and validation status. Distinguish optical
layers from mutually exclusive surface populations. A Mix Shader of two Principled
surfaces is a spatial/statistical mixture, not arbitrary vertical optical layering.

Use the Principled families that the finish needs: dielectric or metallic body,
reflection width and direction, outer coat, aggregate sheen, transmission,
subsurface or volume. Keep thickness, opacity, absorption, coat weight and coverage
meanings separate. For complex paint, a useful architecture is pigment plus
oriented metallic-flake populations with a common outer interface, independently
controlled coat relief, and optional separate surface deposits. Emission is not
a substitute for physical flake sparkle. Cloth microflake sheen is not car paint.

Read [mapping recipes](references/mapping-recipes.md) for metric triplanar fields,
three-sample triangular-lattice hex synthesis and normal composition. Preserve
one shared field/seed/transform contract across correlated channels. Keep long
veins, grain, weave and directional brushing out of stochastic synthesis unless
their structure tolerates it.

Keep substrate Normal and Coat Normal separate when their physical interfaces
differ. Explicitly connect a geometric normal for an intended smooth interface
when node defaults or inherited normals are ambiguous. For tangent maps retain
the active render UV set and explicit source corner normal, Mikk tangent and sign
through export. The tested explicit-frame producer admits modifier-free Meshes
without shape keys and rejects named nonactive UV routes; qualify other paths
separately rather than generalizing that frame proof to evaluated modifiers.
For height use physical amplitude, a valid coordinate field and supported Bump
derivatives; do not infer relief from color brightness merely to add detail.

## Make an RTPT candidate

Read [RTPT capabilities and qualification](references/rtpt-capabilities.md) before
accepting a new appearance-critical mechanism. Prefer a deliberate body/coat
structure with complexity in coordinate and spatial input fields, while retaining
distinct physical lobes where their response matters. Do not pre-collapse a
material solely because RTPT distills it. First inspect what the installed path
actually preserves, then document any necessary approximation.

RTPT has a constrained distilled BSDF and separate caching/filtering behavior.
Procedural input math does not inherently require texture baking. General
independent metallic-normal fidelity remains version-dependent: an earlier
ARM64 study passed PT normal controls but failed RTPT controls. Treat that as a
bounded observed limitation, not a universal ban on flakes or complex materials.

## Review and deliver

Use one representative target surface and a fixed camera/light/display setup.
Reuse established fixtures. Check a useful ordinary view and, when unresolved
microstructure matters, a closeup. For a new uncertain mechanism use one matched
control and restoration that distinguishes it; reuse existing evidence for
unchanged paths. Inspect actual completed native images and their receipts.
Do not create a mandatory full feature matrix for every material or expand tile
look-development tests. Test motion only when claiming temporal stability.

Report stages separately: authored graph, translated/bound graph, native image,
mechanism-qualified appearance, saved library and target-scene application.
Deliver an editable material with assets, metric coordinates, independent controls,
the inspected image and mode-specific limitations. Source changes require the
project's engineering note, revision, tests and installed/native status. Preserve
existing scene ownership, sparse updates and manual save/publish rules.
