# Image-guided existing asset refinement

## Project adaptation

This is a generalized workflow. Use the active project's source, scene, renderer
and save/publication rules. Names such as `HANDOFF.md`, room XML, specialist
profiles, `blender/tools/`, studio assets and pipeline contracts are integration
examples, not files supplied by this skill. Discover their maintained equivalents
before using them. Only helpers inside this skill directory are bundled. If a
required adapter or asset is absent, report that stage as unavailable and deliver
the supported work; do not invent a command, schema or successful native result.
Use specialist roles only when delegation is authorized and available; otherwise
the coordinator performs the same bounded work. Keep one live Blender owner.


Read HANDOFF, AGENTS, specialist CONTRACT and existing source/pipeline contracts.
Use existing_asset_refiner for source/appearance coordination; root retains exclusive
live integration, native review and permitted saves. Use cabinetry-refinement for
cabinet/room constraints and room-variations for existing look ownership. Other assets
use their actual source/installation contracts; do not apply cabinet rules universally.

## Establish authority and coverage

Locate the rendered asset's editable source, stable IDs, placements, material/UV
ownership and current appearance. An image alone cannot authorize claims about hidden
construction or recover exact dimensions. If source cannot be identified, obtain it
or deliver a clearly bounded concept; do not pretend an in-place CAD edit occurred.
Inventory the latest requested asset/room coverage. Separate fixed fit/envelope/mounts
from authorized internal construction refinement. Record numeric before/target/after
constraints and approved deltas; retain source hashes and stable integration identities.

## Turn an attractive image into a buildable target

Use imagegen skill/tool when generating. Edit the actual input render toward credible
fabrication of that object, preserving fixed layout, scale, camera and material choices.
Use reference photographs where available. Generate a whole-asset target plus the few
joint/edge/interior close-ups needed to make construction legible. Inspect drift; image
generation is design intent, not factory evidence or a measured scan. Ask for concept
acceptance only when requested or a material/design choice genuinely needs user input.

Translate the target into an ID-based delta ledger BEFORE implementation:
feature/region → existing source owner → physical construction/operation → dimensions
or estimate → material/UV intent → target crop → proof/acceptance. Capture more than
recoloring: separate boards/shells, seated contacts, plausible wall/stock thickness,
recesses/lips, edge profiles, hardware mounts and finish-specific surfaces as visible.
A simple wood box may need side/bottom panel ownership, fitted corners, concealed
plywood edging or solid endgrain, inset lid/reveal and selective edge easing. Choose
its actual evidenced/accepted construction, not a generic dovetail on every box.
Metal, ceramic, fabric and plastic need their own fabrication models, not wood joins.

## Preserve accepted decisions through iteration

Maintain current accepted choices in the checkpoint/brief: profile type (roundover,
chamfer or compound), size, edge coverage, covered/exposed core, grain/construction,
finish and fixed constraints. Later 'stronger bevel' does not revoke an accepted soft
roundover or covered edge. Resolve ambiguity from session context before asking.
Do not alter unrelated channels when user requests only edge softness/size.

Prove the actual cross-section: arcs/radius for roundovers, planar angle/width for
chamfers; smoothing cannot turn one into the other. Verify receiving/bearing contacts
remain correct. Choose physical size from construction/reference and accepted intent,
not universal 3mm kitchen defaults. Compare one representative actual exported profile
and native fixed-camera highlight before applying it broadly. A default radius present
in source is not proof it matches target appearance. Match strong, visible accepted
craftsmanship rather than automatically shrinking details to 'subtle' defaults.

## Reuse the specialist stack

product_detail owns reference/construction evidence and gaps; luacad_modeler owns
assigned existing CAD detail using fidelity modeling/all LuaCAD methods; material_specialist
owns coherent finish/scale/region recipes; asset_preparer owns isolated bounded save/reopen
proof. Delegate disjoint assignments with shared IDs, latest decisions and target crops.
At limited concurrency, stage/reuse roles; never repurpose a research role to own source
without explicit ownership. Report native profile versus saved-instruction fallback once.

Image-generated material maps are distinct from the lit concept. Validate multiscale
pattern, physical scale, grain/path direction, seams, surface regions and native shader
response via material-reference-lookdev. Use construction-aware face/edge/endgrain/coat
assignments, not random textures or bounding-box stretching. Scalar channels are valid
where supported; don't fabricate relief just to populate all PBR maps.

## In-place delivery and comparison

Validate source topology/dimensions separately from render-normal/UV/material gates;
use current adapters and source-bound receipts. Root replaces changed Mesh data/appearance
under retained Objects, poses, mounts and dependencies; standalone asset is intermediate.
Scope imports/rebuilds to changed source/dependencies; appearance-only skips CAD rebuild.
Inspect same-camera whole result and target-relevant detail crops at useful resolution.
Keep exposure/light fixed to diagnose detail versus style. Reuse completed evidence.

When showing a revision, bind the image to current source/asset hashes and profile choice;
do not present old or in-progress images as current. State rendering status accurately.
Deliver coverage/remaining estimates, target-versus-result deltas and source/applied/saved
state separately. Retain successful authorized replacement and verify local persistence
under project rules; don't automatically restore old geometry after review. Publication
and turntables require explicit requests. No new native fidelity claim without inspection.

## Lessons from source-backed vanity refinement

Treat a crude blockout as an installation envelope, not an approved furniture design.
For requests to make it a believable built product, allow concept proposals to change
internal front count, frame/rail/stile arrangement, reveals, joints and hardware while
preserving fixed outer dimensions, room fit and functional anchors. Do not 'correct'
a credible paired-door proposal back to an awkward single door solely because the
blockout had one. Keep explicit user layout locks when present; meaningful redesign
proposals pass the requested concept gate before source implementation.

Stable identities mean traceable integration lineage, not an immutable part count.
Reuse existing suitable/hidden identities deliberately; declare new constituent IDs
and retire obsolete ones in source with a mapping. Verify parents, placements and
unaffected assets. Never duplicate existing owners or hide obsolete leftovers silently.

When matching room character is requested, inspect surrounding materials and hardware
before concept generation. Propose fitting scale, silhouette, mounting and finish,
not just a sampled metal color. Material/finish matching does not identify an exact
alloy or measured coating. Keep sink/plumbing/appliance proxies outside refinement scope
unless requested. Select a context camera where the refined object and relevant room
accents are actually visible; an approved primary view can be poor comparison evidence.

Before full integration, test changed geometry through its actual unit conversion,
world/local transform and stored-float consumer projection. Source topology and a private
origin-centered blend can pass while small triangles collapse after placement. Localize
the defect; retain raw CAD authority and use only source-derived datum conditioning or
same-surface retriangulation with bounded recorded deltas. Do not broad-weld, smooth over,
relax normal gates or apply a universal epsilon. After repair validate affected parts,
retain unchanged Mesh data, recheck cached import survival and perform permitted saved-file
readback. Reuse current implemented precision diagnostics rather than create another
parallel task importer.
