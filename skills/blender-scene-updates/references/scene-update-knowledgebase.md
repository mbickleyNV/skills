# Incremental Blender scene updates

The saved Blender scene is authoring authority. USD bootstraps native rendering
and remains the interchange/fallback path. Supported edits compile directly from
current evaluated Blender owners to typed OVStage writes; routine captures do
not replay historical decisions or audit the entire house.

Current boundary: Blender 5.2.2 LTS (Linux ARM64 community build), OVStage **0.2.0.377349**, OVRTX **0.5.0.377615**,
public SDK/OVStream. Current source is under
`scratch/ovstream-durable-addon/public`; the older
`scratch/ovstream-shm-push-addon/public` is implementation evidence.
The Blender 5.2 typed scalar driver admission correction is installed; see
[upgrade and cold-export validation](engineering-changes/blender-522-cold-driver-fix.md).
This document describes implemented routes and their current limits, not a
request to upgrade the installed backend. Read the current `HANDOFF.md` for
installation and live ownership.

## Compile changed owners once

`direct_scene_updates.py` coordinates category adapters before generation work.
Bootstrap captures original ID/session-UID handles, prim/schema contracts,
shared-data users, parent dependencies and accepted presentation once. Planning
uses nominated owners and their dependency closure, not a scene-wide shader or
mesh inventory. Identity comes from original IDs; geometry and pose come from
current evaluated output. Temporary mesh extraction is released after copying.

Geometry/transform/shading notification flags retain unknown values through
coalescing. Cheap controls protect namespace, parent, membership, modifiers,
visibility and effective material assignments. Shared Mesh users cannot silently
write conflicting values to one native target. Light-data notifications retain
resolved Object controls, and ancestor scale updates refresh dependent lights.
Unknown or unsupported output returns a concrete fallback reason.

Visibility-only observations are neutral when coalesced with known depsgraph
flags, rather than erasing their evaluation context. Mixed edits retain the
visibility proof even if another object requires population. Mesh assignment
repair uses changed Object handles and touched data-user buckets, never a new
scene-wide owner search. These changes do not remove older scene-wide work in
variation recall or bootstrap; they keep it out of the new owner repair path.

Physics geometry has a separate consumer route. Raw Cube size and Mesh points
writes acknowledged successfully but left collisions unchanged. A current inline
geometry contribution recooks those shapes while keeping Stage, PhysX owner and
simulation time. CPU static/dynamic primitive and convex-mesh contact tests pass;
a recreated dynamic actor receives its previous pose and velocity, retaining the
new inertia. The existing geometry-only generation adapter can reuse that owner.
This is not a claim that physics updates bypass Blender export preparation.
GPU, kinematic and joint-attached shape changes retain replacement. The new CPU
proofs do not alter the installed runtime admission policy or relabel old results.

## Bounded current projection and acknowledgment

The coordinator retains one **current** value per native attribute, not an edit
history. Contracts advance only after complete native acknowledgment. Visibility notifications compare against that accepted current state, so returning to the original exported value is still an edit. A failed
or incomplete packet preserves pending work and cannot mark the revision applied.

`direct_projection_ack.py` tracks one version per current attribute and pending
keys. With the same native population token, an unchanged capture selects no
rows in **O(1)**; it does not reconstruct geometry values or ask client hashing
to rediscover equality. A small edit selects only pending rows. A changed worker,
client/session state or successful population revision requires the current
projection to be replayed. Camera/value updates do not invalidate that token.
Unknown/recovering native state is not certified reusable.

Direct writes make bootstrap USD stale. Before any population fallback, include
the resolved directly changed Object/Material/World owner closure alongside the
new edit. Re-sample those owners from Blender so an unrelated fallback cannot
restore older appearance or geometry. A newly accepted population recaptures
contracts. Consumer switches use the same current-state reconstruction; cached
old presentation layers are not substituted into an unprepared F12/viewport.
